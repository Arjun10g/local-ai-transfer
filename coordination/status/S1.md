## Work completed

- Added v0.1.0 Engine API and error-code contracts with lifecycle, route/auth, stream, session, and cancellation semantics.
- Added dependency-free C++17/CMake fixture engine with repository-owned `EngineBackend`, deterministic CPU fixture backend, lifecycle states, bounded four-session store with oldest-first eviction, atomic generation commit semantics, cancellation, and metadata-only metrics.
- Added loopback-only HTTP server with ephemeral port support, bearer auth, origin check, 64 KiB body cap, request IDs, health/readiness/version/build-info/probe/metrics/session/chat/cancel routes, SSE framing, and clean worker joining on shutdown.
- Added `version`, `print-build-info`, `probe`, `verify-model`, and `serve` commands. Build/probe output reports whether pinned llama.cpp CPU support is compiled; fixture mode opens no model or network client.
- Added a bounded strict JSON chat-envelope parser. It preserves full ordered `system`/`user`/`assistant`/`tool` history, rejects unknown/duplicate fields, unsupported roles, malformed values, oversized history, non-integer limits, late system messages, and histories without a user message.
- Added the same-pin official llama.cpp Jinja evaluator (`common/jinja`) around the GGUF-embedded template. Real generation has no raw-prompt fallback; `normal` supplies `enable_thinking=false`, `deep` supplies `true`, and absent/invalid templates fail closed. The pinned public C API has no template kwargs surface, so no stronger override is claimed.
- Added prompt-plus-generation context-budget enforcement, mode/template fixture assertions, and HTTP negative coverage for ordered messages, unknown fields, lookalike roles, fractional limits, and late system messages.
