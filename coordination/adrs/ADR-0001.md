# ADR-0001 — Local Assistant Model, Artifact, and Runtime Architecture

- **Status:** Accepted
- **Date:** 2026-09-04
- **Decision owner:** S0 Sol
- **Authors/reviewers:** S0; S1–S4 acknowledgement pending
- **Related tasks/risks:** SOL-002; R-001, R-003, R-005, R-007, R-036, R-039

## Context

The project must turn a planning-only archive into a portable local assistant for a restricted Dell Windows x64 laptop. The user has authorized Hugging Face as the current model-weight source and asked that Shadeform practice and local environment configuration be borrowed from the Expert PreFetch project.

## Fixed constraints

- Target: portable Windows x64, foreground, no install or target-side build/download.
- Model: Qwen3.5-9B, one deployable model.
- Offline: core inference, UI, sessions, and local tools require no external network.
- Memory: 8,192-token default; 16,384 only after measured acceptance.
- Security: loopback/auth, bounded resources, strict tools, model and release integrity.
- Dependency: native engine over pinned llama.cpp/ggml; Node.js 24 built-ins only for host.
- Modality: text only; no vision projection.

## Decision criteria

1. Preserve offline correctness and explicit model identity.
2. Fit the observed target memory window with a mandatory CPU path.
3. Permit reproducible remote artifact production and evidence.
4. Keep target deployment portable and dependency-free.
5. Fail closed on unavailable approvals, hardware, or providers.

## Options considered

### Official Hugging Face source, controlled project conversion

- Benefits: satisfies the user's current source direction while retaining official provenance, immutable revision pinning, and project-owned Q4_K_M bytes.
- Costs: remote download/conversion time and artifact storage.
- Risks: provider/source availability and incomplete approval references.

### Arbitrary pre-quantized community artifact

- Benefits: faster initial bring-up.
- Costs: loses controlled conversion identity and can differ in tokenizer/template/tensors.
- Risks: unacceptable release provenance and accidental artifact substitution.

## Decision

Use the official `Qwen/Qwen3.5-9B` Hugging Face repository at an immutable revision as the source on Shadeform. Produce the deployable text-only Q4_K_M GGUF through the pinned project conversion pipeline. A pre-quantized HF artifact may be used only as an explicitly non-release bootstrap fixture, never as the accepted release identity.

The product architecture remains a repository-owned native engine over a pinned llama.cpp/ggml substrate plus a zero-runtime-dependency Node.js 24 host and static UI. CPU is mandatory. Vulkan is the first Intel acceleration candidate; SYCL remains experimental and neither is promoted without exact target evidence.

## Rationale

This reconciles the user's HF instruction with the stronger provenance and offline requirements in the execution pack. It also keeps expensive/model-heavy work off the target while allowing a reproducible, inspectable release.

## Consequences

### Positive

- Official source identity and license can be pinned and hashed.
- Target never contacts Hugging Face.
- The product can reject any unrecognized GGUF despite a familiar filename.

### Negative / accepted trade-offs

- The first real-model run depends on a successful controlled remote artifact job.
- Final Intel acceleration and target acceptance remain blocked on a Dell receipt.

### Required implementation changes

- S2: source lock, model manifest, conversion and Shadeform job.
- S1: strict verifier and pinned backend adapter.
- S3: host/runtime boundaries and text-only UI behavior.
- S4: provenance, package, secret/weight and acceptance tests.

## Validation

- Experiment/test: fixture vertical slice, controlled J1M artifact job, oracle/product parity, offline suite, package scan, exact target check.
- Acceptance threshold: `execution/ACCEPTANCE_CRITERIA.md`.
- Artifact: content-addressed Shadeform evidence plus committed indexes.
- Revisit trigger: official source incompatibility, controlled Q4 failure, or target memory/correctness failure.
