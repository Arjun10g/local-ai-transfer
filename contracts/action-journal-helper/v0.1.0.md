# Foreground ActionJournal helper/transport ABI v0.1.0

This is an inert source contract. It adds no CMake target, production Node
import, package file, launcher path, trust anchor, service, or runtime
availability. `PRODUCTION_ACTION_JOURNAL_PROTOCOL_AVAILABLE` and production
ActionJournal availability remain `false`.

## Authority and startup

The future supervisor sends one fixed, bounded bootstrap record through an
inherited anonymous pipe exposed as standard input. Standard input must itself
be a pipe. The 32-byte HMAC key and 16-byte session nonce never occur in argv,
the environment, a pathname, pipe name, disk, status, receipt, or error. The
helper reads the record once, rejects trailing data, and zeroes secret buffers
after the single client session.

The inherited bootstrap is a fixed 192-byte little-endian header followed by
two exact, unterminated UTF-16LE strings. Offsets, lengths, identity fields,
reserved-zero region, and the synthetic byte vector are machine-defined in
the adjacent JSON contract and fixture. An unclosed writer is refused because
observing zero currently-available bytes alone would leave a trailing-write
race.

Before creating a named pipe, the helper opens the existing fixed journal file
through the merged Win32 storage boundary with the exact expected volume,
file, and container identity. It retains the complete storage lease—not merely
a pathname—for the helper lifetime. Startup scans the fixed header and every
bank, rejects malformed or conflicting committed authority and duplicates,
applies the merged active/terminal caps, and durably appends conservative
startup recovery events. No pipe is visible if storage or recovery is unsafe.

## One local authenticated client

The server creates one overlapped byte-mode named-pipe instance with
`PIPE_REJECT_REMOTE_CLIENTS`. A protected current-user DACL contains exactly
one noninherited allow ACE. After connection, the helper binds the peer to the
bootstrapped PID, retained process handle and creation time, exact token-user
SID and session, and an exact no-follow image file identity. The process and
image handles remain held until disconnect.

Every connect, read, and write has an event-backed `OVERLAPPED`, a finite
deadline, `CancelIoEx` on timeout/cancel, and a checked cancellation result.
Failure to prove completion or cancellation closes the session. There are at
most eight queued frames/requests, 1,024 frames per direction, and 65,536 bytes
per frame.

Frames are the exact merged v0.1.0 canonical JSON protocol. HMAC-SHA256 covers
the protocol domain and canonical envelope without `mac`; comparison is
constant-time. Request and response directions have independent sequences
starting at zero. Nonce mismatch, duplicate request ID, sequence replay/gap,
unknown fields, malformed UTF-8/JSON, wrong key order, deadline failure, or
correlation failure is fatal to the session.

## Durable transitions and lost acknowledgement

Every mutation first validates the complete transition and capacity from a
fresh scan of committed authority. The inactive bank then receives staging
marker, body, and committed marker with a full `FlushFileBuffers` and exact
handle readback at each barrier. Once the commit sequence begins it is
noncancellable; cancellation cannot leave a response that authorizes replay.

A response lost after commit is recovered only by a new authenticated session
and `detail`. `dispatch` and later mutations are never replayed. An exact
duplicate `prepare` may return its still-prepared receipt only when its
persisted binding digest matches; otherwise it fails closed.

Only finite redacted protocol receipts leave the helper. Paths, SIDs, image
identity, action arguments, previews, provider data, content, URLs, command
output, credentials, key material, nonce, and free-form diagnostics do not.

The exact machine ABI and remaining Windows/packaging/target gates are in
`v0.1.0.json`.
