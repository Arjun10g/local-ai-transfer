# Windows process transaction v0.1.0 — phase 2a topology

This contract is source-only and unavailable. `SupervisorState` is the sole
process-lifetime owner of the private `JournalAuthorityOwner`. The pipe server
and process transaction borrow it only while the supervisor lifetime proof is
held. The helper accepts a move-only pipe ticket and the process transaction a
move-only, one-use launch authority; neither accepts a raw owner or
supervisor-only entry. Construction requires an explicit canonical `StorageRequest` startup
handoff; there is no default or fallback storage selection.

Operation, session, request, and stable registry identities are complete
`std::array<uint8_t, 16>` values. Canonical lease binding carries request and
call references, tool/risk/side-effect labels, argument/preview/operation
digests, authorization kind, sequence-one authorization, and receipt/event
proof digests. No integer truncation, hash coercion, callback journal flow, or
parallel supervisor journal authority is permitted.

Shutdown first closes pipe-call admission and joins any helper call, then
stops the pipe and releases its long-lived ticket. It closes process admission,
drains the process fence, children, and process borrow tickets, then drains
remaining tickets before destroying leases and releasing the owner last. The shared
bounded control word linearizes close/acquire and wakes drain waiters; a
same-thread/reentrant or timed-out drain is a finite refusal/fail-stop, never
a deadlock. No owner lock is held while waiting.

Phase 2a hard-refuses before lease persistence, external-dispatch admission,
process creation, or any irreversible mutation because the accepted lease has
no proof issuer and external-proof authority is false. A separately reviewed
phase-2b OS-handle evidence verifier is required before any future dispatch
implementation. This phase adds no issuer, friend, factory, mint, or fake
proof seam. Product/controller registries remain untouched.

The phase-3 controller handoff field is versioned as
`native-supervisor-handoff.v1`. For Windows `app.open` and
`process.run_allowlisted`, its exact owner value is the internal literal
`journal_dispatch_owner: "native_supervisor"`; callers and model arguments
cannot override it. The current controller records the complete typed binding
only as an unaccepted internal description, then closes the authorized
pre-dispatch operation with `failed_definitive` because no native bridge or
proof authority exists. It performs no Node spawn or fallback. If a future
handoff is accepted, the controller performs no `dispatch`, `acknowledge`,
`begin_reconciliation`, `complete`, `fail_definitive`, or `mark_unknown` call
for that operation; the native supervisor owns those transitions. An accepted
handoff may never use `failed_definitive`; only a provably pre-handoff failure
may do so.
