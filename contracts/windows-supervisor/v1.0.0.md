# Windows supervisor-authority contract v1

This is a source-only, unlinked contract for a future Windows foreground
supervisor. It is not a process launcher, host capability, package component,
or release approval. All availability and activation flags are false until a
reviewed release manifest, self Authenticode identity, package identity,
cancellable-I/O proof, and durable ActionJournal authority are supplied by a
future integration.

The eventual supervisor has one foreground owner of a root Job configured with
kill-on-close and a bounded active-process limit. The current policy is direct
root membership; nested jobs are refused until a signed build proves the
platform policy. Every child has a stable registry entry until it is reaped. A
missing, ambiguous, or changed identity refuses; there is no shell, search,
PATH lookup, detached-child fallback, or leader-only cleanup.

Executable and working-directory identities are broker-issued opaque handles
and fixed identity records, never caller-provided path claims. Bootstrap is
limited to anonymous inherited handles and binds parent and pipe-server PID,
creation time, token SID/session, image identity, file identity, and exact pipe
direction/relationship. The retained executing-image section identity gate is
currently false, so the pathname-reopen reference path cannot authorize
bootstrap. `CreateProcessAsUserW` also consumes a working-directory pathname,
not a retained directory handle, so the stable-cwd identity gate is false.
The supervisor-owned process-transaction acceptance gate remains false.
Launch/session capabilities are generated in memory from CNG
randomness, scoped to one closed enum, expiring, and journal-bound; the issuer
retains its signing key and consumers receive only a verifier capability. The
MAC covers the operation, argument, and preview digests. Capability keys,
nonces, bearer material, handles, argv, environment, and paths are never
written to disk, put in argv/environment, or returned in receipts. The
loopback entry is metadata-only in this slice; it does not issue a bearer.

Every cancellation, deadline, broker shutdown, I/O failure, identity change,
or lost acknowledgement is a bounded whole-Job termination/reap or an
unknown/manual outcome. Secret buffers are zeroized, nonce reuse is rejected,
and owned handles are closed by RAII. The journal start record is persisted
before dispatch and the terminal record before acknowledgement; persistence
failure returns a typed persistence-failure outcome and leaves the state
unknown. A private adapter can reload the latest validated record after
restart; a durable start reloads as dispatched-unknown, never as a harmless
pre-dispatch failure. Only a terminal record can open the next operation, with
a higher sequence and a fresh nonce. Two sequence numbers are reserved before
provider code is called; UINT64_MAX-1 and UINT64_MAX therefore refuse before
dispatch, while post-callback persistence or sequence failure remains typed
ambiguous. The reference tests exercise ordering, recovery, and refusal only;
Windows API compilation, target process evidence, helper/package wiring, and
production availability remain unproven and disabled.
