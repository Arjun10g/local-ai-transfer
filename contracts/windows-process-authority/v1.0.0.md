# Windows process authority contract v1.0.0

This is a dormant, source-only contract. Every availability and activation
flag is false; it is not a launcher, broker, package declaration, proof
issuer, or readiness receipt. The existing process transaction therefore
refuses before journal mutation, child creation, or external execution.

## Required future boundary

A future Windows implementation must receive a private, noncopyable,
supervisor-minted `LaunchAuthority`, not a public POD or caller-supplied proof.
Its `UniqueHandle` members own each HANDLE and close it exactly once. The
authority binds a read-only executable handle and its containing directory to
the canonical absolute manifest path, size, volume/file identity, and SHA-256,
and separately binds a no-reparse working-directory handle. The
`absolute_manifest_path_binding` and `no_reparse_components` predicates are
required and stored on both bound file identities, and symlink, junction, and
reparse-point rejection is non-negotiable under
`governance/SECURITY_AND_TOOL_POLICY.md` §9. It also binds the
operation's exact 128-bit ID, generation, and nonce, plus token, Job, and
cancellation-event handle identities. The owner must recheck each identity
after opening and retain the handles through the transaction. Paths, handles,
argv, environment values, prompts, and credentials are never receipt fields.

Before a child exists, its supervisor-owned Job/containment object must already
exist with kill-on-close and whole-tree termination semantics. The future
implementation must use a least-privilege token, prohibit ambient handle
inheritance, and prove zero active processes before releasing the authority.
There is no valid “create suspended, then attach” window.

The child environment is a fresh implementation-owned fixed allowlist
(`SystemRoot`, `WINDIR`) with an authenticated allowlist digest. Caller maps
and inherited credentials, proxies, SSH handles, and user configuration are
forbidden; the `exact_allowlist`, `credentials_excluded`, `proxy_excluded`, and
`user_config_excluded` proof fields are all required.

## Arguments and command line

The Windows process-creation API takes a single `lpCommandLine` string rather
than an argument array, so argument-to-command-line quoting is the injection
surface that `AGENTS.md` ("spawn executable plus argument array; never
concatenate an unrestricted shell command") and the process policy in
`governance/SECURITY_AND_TOOL_POLICY.md` §10 address. This contract therefore
requires, and `native/windows_supervisor/launch_authority.hpp` stores and
checks, the following predicates:

- `argv_array_only` — the bound value is an ordered array of UTF-16-safe
  strings. `argv[0]` is never caller supplied; the image is bound by handle and
  canonical absolute path.
- `command_line_escaping_fixed` — the future native layer builds
  `lpCommandLine` with exactly one fixed, documented escaping algorithm: the
  `CommandLineToArgvW` / MSVCRT parsing rules (backslashes are literal except
  immediately before a quote, where they are doubled; each argument is quoted).
- `command_line_round_trip_verified` — the built command line is parsed back
  and must compare equal, element by element, to the bound array before launch.
- `no_shell_or_concatenated_command_line` — no shell, no command interpreter,
  no concatenated or caller-supplied command string ever reaches a launcher.
- `utf16_safe_arguments` and `argument_count_and_length_bounded` — at most 64
  arguments, at most 8192 UTF-16 units each, at most 30000 UTF-16 units total,
  no control characters, and a bound 256-bit argument digest.

This revision binds and validates the obligation only. It builds no command
line and launches nothing.

## Cancellation and orphan state machine

Cancellation belongs to the supervisor, has a bounded join, and closes
containment on supervisor death. Generations are not caller supplied: `begin()`
takes no argument, derives the run generation from the authority's issued
generation anchor, and returns it. The generation is strictly increasing within
one authority and bounded to eight runs. Every other transition takes a
generation that must equal the current active generation exactly and is
otherwise a typed refusal that changes no state.

- `unknown_manual` is **terminal** for an authority instance. `begin()` is
  refused from `running`, `cancel_requested`, and `unknown_manual`; restart
  after an orphan or after any cancellation requires a freshly issued authority
  carrying a new generation anchor from the issuer.
- Orphan marking is fenced by the same generation and state guard as every
  other transition, so it cannot be used to escape a running transaction into a
  restart.
- A completion for an authority that never started is a typed refusal and must
  not poison the state to `unknown_manual`.
- A bounded cancel join that times out with children still live transitions to
  `unknown_manual`, not back to `cancel_requested`.
- A completion that races an in-flight cancel is recorded as `unknown_manual`,
  never as success.

An ambiguous or late outcome is `unknown_manual`, not a retry or fabricated
success. The full transition table is enumerated in the header comment of
`native/windows_supervisor/launch_authority.hpp` and in
`native/windows_supervisor/README.md`.

The C++ proof shape is in
`native/windows_supervisor/launch_authority.hpp`. It is *listed in* the
default-OFF inert Windows compile-check target through `authority.cpp` — listed
only: that target is gated OFF and hard-fails off WIN32/MSVC, so this header
has never been compiled by anything — and it is outside the product CMake
graph. Its availability constant is false and the current
transaction validates it before consuming the process borrow or reaching any
future mutation boundary. Native verifier,
Windows SDK/target race evidence, a proof issuer, durable journal bridge, and
explicit product activation remain required. No browser, Copilot, provider,
or model path is changed by this slice.
