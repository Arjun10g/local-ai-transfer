# Windows process authority contract v1.0.0

This is a dormant, source-only contract. Every availability and activation
flag is false; it is not a launcher, broker, package declaration, proof
issuer, or readiness receipt. The existing process transaction therefore
refuses before journal mutation, child creation, or external execution.

## Required future boundary

A future Windows implementation must receive a supervisor-owned proof, not a
request path or a pathname that it reopens. The proof binds a read-only
executable handle and its containing directory to the absolute manifest path,
size, volume/file identity, and SHA-256, and separately binds a no-reparse
working-directory handle. The owner must recheck each identity after opening
and retain the handles through the transaction. Paths, handles, argv,
environment values, prompts, and credentials are never receipt fields.

Before a child exists, its supervisor-owned Job/containment object must already
exist with kill-on-close and whole-tree termination semantics. The future
implementation must use a least-privilege token, prohibit ambient handle
inheritance, and prove zero active processes before releasing the authority.
There is no valid “create suspended, then attach” window.

The child environment is a fresh implementation-owned fixed allowlist. Caller
maps and inherited credentials, proxies, SSH handles, and user configuration
are forbidden. Cancellation belongs to the supervisor, has a bounded join,
and closes containment on supervisor death. An ambiguous or late outcome is
`unknown_manual`; it is not retried or converted into success, and a late
completion cannot mutate a later run.

The C++ proof shape is in
`native/windows_supervisor/launch_authority.hpp` and is intentionally not in
the product CMake graph. Its availability constant is false and the current
transaction checks it before any future mutation boundary. Native verifier,
Windows SDK/target race evidence, a proof issuer, durable journal bridge, and
explicit product activation remain required. No browser, Copilot, provider,
or model path is changed by this slice.
