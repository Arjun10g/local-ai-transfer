# Native ActionJournal client adapter v0.1.0

This is an inert, test-injected adapter over the merged
`lae.action-journal.v0.1.0` protocol. The production availability constant is
immutable `false`. The host, tool registry, package, launcher, pipe discovery,
and capability gates do not import or select it.

## Exact recovery and duplicate boundary

Before a mutation the adapter derives the exact helper event digest from the
authenticated prior receipt, operation ID, method, canonical request body,
result state, authorization, and resolution. A lost acknowledgement does not
replay a mutation. On a new authenticated session, the final durable detail
event and high-water receipt must equal that exact derived event. A terminal
state match by itself is never proof. Only `prepare` has one exact retry, using
the helper's deterministic prepare binding.

Within a client lifetime, unresolved operations are indexed by exact
`tool_name + arguments_digest`; changed request/call IDs do not create another
authority. At startup the public protocol intentionally exposes no tool or
argument digest. The adapter therefore does not guess: any active record that
the helper has not recovered to `unknown_manual` blocks all new prepares, and
unknown records block until explicit manual resolution.

## Test transport and settlement

The injected factory, `read`, and `write` operations accept an `AbortSignal`
and absolute wall deadline. The separate close transaction accepts an
`AbortSignal` but uses its own trusted monotonic deadline. For normal
transport operations, after deadline the adapter aborts, waits a
short settlement grace, then marks health
`action_journal_transport_settlement_unproven` if the operation is still live.
It nevertheless continues waiting and does not return or reconnect until that
operation actually settles. Thus an uncooperative injected operation can hold
the caller indefinitely; it cannot become a late mutation after a returned
failure. A production implementation needs the merged native supervisor and
cancellable I/O boundary rather than this JavaScript seam.

Incoming transport chunks must be `Uint8Array` views over `ArrayBuffer`.
`byteLength` and cumulative response length are rejected before the decoder
makes a client-side copy. At most eight chunks and 65,536 response bytes are
accepted.

The factory supplies an exact standalone 32-byte transferable `ArrayBuffer`.
Ownership is transferred so the supplied view is detached. After a settled
close, mutable key buffers owned by the adapter and protocol receiver are
zeroed. This does not claim that a factory erased copies made before return,
nor that JavaScript immutable nonce/request strings, parsed objects, or prior
frames can be securely erased. Those limitations keep production activation
blocked.

Factory results are inspected through data descriptors only: accessors are
never invoked, reflective failures are caught, and an independently
accessible standalone key is captured before transport and shape validation.
JavaScript cannot inspect a Proxy without allowing its reflective traps to
run; trap failures are caught and the envelope is refused. Inaccessible key
material is not proven zeroed. Malformed results are rejected with bounded
cleanup of any safely captured transport and key; a rejected close retains
that transport/key as poisoned ownership until quiescence is proven. A clock or request-ID
failure before transport dispatch emits the finite
`action_journal_prewrite_invalid` code and never enters lost-ACK recovery.
If the clock fails after a factory has returned, the raw result is still
retained for deterministic close and key zeroing.
An ownership-settlement slot is registered before every factory invocation.
Every fulfilled raw result is first captured by that slot and then either
adopted by the live connection or routed exactly once into the retained close
transaction; a close epoch cannot discard a fulfilled result.

Only finite codes and protocol-validated redacted receipts/events leave the
adapter. Caught error text, key material, nonce, paths, identity, raw arguments,
previews, content, and provider payloads are not returned.

Close is a separate cleanup transaction. It atomically detaches the current
connection, blocks new dispatch/reconnect, invokes the captured close exactly
once, and uses only a trusted monotonic timer for timeout and grace. A timeout
aborts close and then remains pending until that same close settles. A close
rejection retains poisoned ownership and returns the finite
`action_journal_close_unproven` error; transport/key state is cleared only
after confirmed quiescence and zeroization. Concurrent and repeated calls
share the same close promise. The close request increments an epoch and aborts
in-flight cooperative operations immediately; every queued or recovery step
checks that epoch before factory/I/O/state transitions, so it cannot reconnect
or complete after close was requested.
The close operation is the exception to the injected wall-deadline wording above:
it receives only an abort signal and is bounded by the separate trusted monotonic
cleanup timer.
