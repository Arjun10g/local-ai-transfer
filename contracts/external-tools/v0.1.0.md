# External tool contract v0.1.0

This contract is additive to the canonical tool-call and tool-result envelopes. Provider implementations may add metadata to host-only audit events, but model-visible results remain bounded text in the canonical result envelope.

## Common provider states

Exactly one state is reported per provider:

- `disabled` — not enabled in local configuration.
- `unconfigured` — enabled but missing a non-secret prerequisite.
- `unauthorized` — no valid account authorization is available.
- `ready` — configuration and runtime checks passed.
- `offline` — network is unavailable or administratively disabled.
- `failed` — provider returned a typed operational failure.

Mock/fake transports report `mock` in test-only build metadata and must never report `ready`.

## Permission profiles

The host accepts one of four operator-controlled permission profiles for each capability:

- `always_ask`
- `ask_before_writes`
- `review_important_actions`
- `full_access`

The model never supplies this value. A grant record binds profile, capability, provider identity, account fingerprint, workspace/root or browser-session scope, creation time, expiry, and a random generation. Changing provider/account/scope invalidates it. `full_access` may suppress routine in-scope confirmations, but the immutable safety floor in ADR-0002 still confirms irreversible/high-impact actions and rejects T4 actions.

## Result projections

Mail list results contain only opaque message ID, received time, sender display/address, subject, unread flag, importance, and a bounded preview when the approved scope permits it. Full recipients, headers, body, attachments, tracking pixels, and remote resources are excluded.

Mail read results contain the same metadata plus bounded normalized plain text. It must identify truncation and must not return authentication or transport headers.

`mail.search_messages` sends the caller's search phrase to Microsoft Graph and
is therefore a T2 `external_query`, not a pure read. Its preview discloses the
exact phrase and fixed mailbox destination. `ask_before_writes` and
`review_important_actions` still require confirmation for this outbound query;
only an exact current `full_access` account grant may suppress it. Teams
`search_text` remains a local filter over one already-bounded page and is not
sent to Graph.

Teams chat list results contain only opaque chat ID, bounded topic/type, and a strict UTC last-updated time. Channel lists contain opaque channel ID, bounded safe name/description, and membership type. Teams message results contain opaque message/reply ID, strict UTC times, bounded sender kind/display name, normalized text, and importance. Member rosters, tenant/user IDs, attachments, reactions, hosted content, and web URLs are excluded.

Collection pagination never exposes or follows a model-supplied URL. A Graph
`@odata.nextLink` must preserve the exact HTTPS Graph origin, endpoint path,
and initiating fixed query; only one bounded skip token/offset is accepted.
The adapter stores it behind a one-use, account/tool-bound opaque cursor.
Graph read projections are exposed by the controller only when the adapter's
private attestation matches the exact validated serialized payload. Unattested,
cloned, or modified Graph-shaped results become one fixed unverified summary.

Browser inspection returns an opaque browser session ID, canonical current URL, title, page revision, and bounded link candidates. Page inspection additionally returns visible text and safe visible controls, each with an opaque control ID and bounded label/type. Password, file, hidden, disabled, unsafe, and sensitive controls are never actionable. Field entry and control activation require a fresh inspection-bound revision and user confirmation with destination/content disclosure; model input is never interpreted as a selector or script. DOM scripts, cookies, storage, and headers are excluded.

Copilot results contain bounded stdout text, exit class, truncation, duration, CLI version, and declared egress byte count. They never contain the credential source, environment, command line, account identifier, raw stderr, or hidden reasoning.

Process results contain only bounded stdout and byte counts; stderr is discarded
from model-visible output. A process action is an operator-configured,
unsandboxed trust boundary and is therefore advertised as potentially network
capable with `operator_configured` egress. The host never exposes shell,
interpreter, script, PATH, or model-selected executable behavior.

Write previews return a host-generated proposal revision for the confirmation display; callers never invent or supply that value. The controller's private journal binding carries only operation/digest metadata into the provider. Write results return an opaque resource ID, accepted/completed state, timestamp, and digest-only evidence; they do not echo the entire outbound message. A repeated or ambiguous mutation is never represented as an in-memory successful replay or resent automatically. Provider-specific reconciliation must prove the effect or leave it reconciling/manual.

Under `always_ask`, `mail.send_draft` uses two confirmations: a generic, non-content approval to retrieve the existing private draft, followed by a bounded recipient/subject/body preview approval. The host binds the normalized body (up to the contract bound), recipients, subject, identity, and any returned change key/ETag; a changed draft is refused before send. External credential adapters cannot enable `full_access` in production; injected account/transport adapters are test-only fixtures.

## Typed provider errors

At minimum:

- `provider_disabled`
- `provider_unconfigured`
- `provider_unauthorized`
- `provider_offline`
- `provider_timeout`
- `provider_rate_limited`
- `provider_response_too_large`
- `provider_invalid_response`
- `provider_destination_rejected`
- `provider_permission_insufficient`
- `provider_permission_revoked`
- `provider_cancelled`
- `browser_session_stale`
- `browser_link_changed`
- `copilot_cli_unavailable`
- `copilot_policy_denied`
- `process_already_attempted`
- `process_dispatch_limit`

No provider error includes a token, cookie, response body, sensitive URL query, email address, tenant/account identifier, or local file content in default logs.

## Test obligations

- Every positive test has malformed, oversized, timeout, cancellation, and disabled/offline counterparts.
- Fake transports assert the exact method/origin/path/query/header names while replacing authorization values with a sentinel.
- Redirect tests cover cross-origin, downgrade, credential-bearing, loopback, private IPv4/IPv6, link-local, and rebinding-like changes.
- Confirmation tests cover expiry, denial, replay, wrong request/call/session/page revision, double submit, and cancellation.
- Permission-profile tests cover forged/widened grants, expiry, restart, account/provider/root mismatch, revocation during execution, queued-call revocation, immutable confirmation floors, and attempts by model/tool content to select `full_access`.
- Write-provider tests cover recipient/chat substitution after preview, duplicate send retries, partial/ambiguous provider responses, rate limits, cancellation before and after acceptance, and audit metadata without message content.
- Prompt-injection fixtures in mail, Teams, webpages, and Copilot output cannot change provider policy or trigger another tool without a new model turn and normal policy checks.
- Live tests use synthetic accounts/content only and are kept outside the default unit-test command.
